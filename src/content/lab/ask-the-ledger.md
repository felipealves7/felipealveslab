## The question

When someone asks a finance question in plain language, does the system return the right figure, and does it say so when it cannot? A finance team that wants staff to query the ledger without an analyst checking every answer would pay to know.

### Ask your own question (live box)

A small Worker, `ledger-api`, takes one question, asks a model for one read-only SQL query, checks the query itself, runs it on a copy of the same synthetic ledger and shows the query, the rows and a short explanation. Limits: 2 questions per visitor per day, 50 a day for everyone, 300 characters, 100 rows. When a limit is hit or the Worker cannot be reached, the recorded session below stays on the page.

### Model scorecard

## Method and results

**The ledger is invented.** 1,008 rows: six made-up companies, eight made-up accounts, 2025-01 to 2026-09, in thousands of AED. It comes from a fixed random seed, so the same numbers appear every run.

**The semantic layer writes each business word down once.** A question can only be answered if it maps onto one of these definitions. Words that could mean two things, such as "profit" or "costs", are not mapped: the system must ask back.

| Metric | Definition | Words it accepts |
| --- | --- | --- |
| Revenue | Sum of all accounts in the Revenue group. | revenue, sales, turnover |
| Cost of sales | Sum of all accounts in the Cost of sales group. | cost of sales, cogs, cost of goods sold, direct costs |
| Gross profit | Revenue minus cost of sales. | gross profit |
| Gross margin | Gross profit divided by revenue, as a percentage. Zero when revenue is zero. | gross margin |
| Operating expenses | Sum of all accounts in the Operating expense group. | operating expenses, operating costs, opex, overheads |
| Operating profit | Revenue minus cost of sales minus operating expenses. | operating profit, operating income, operating result |

**The translator is keyword rules.** It turns a question into a query: metric, period, entity, grouping, ranking. It is not a language model. That is deliberate. The test set and the scoring work on any translator, so a language model can be plugged in and scored the same way; the model benchmark below does that.

**The test set has 47 questions in four kinds**, each with the right outcome decided by hand. The true figure for each answer is computed from the raw rows by separate code that does not use the semantic layer, so the two cannot share a bug.

**Results.** The translator was right on 40 of 47 (30 correct figures, 10 correct refusals).

| Kind of question | Right | Total |
| --- | --- | --- |
| Plain questions in the translator's own vocabulary | 30 | 30 |
| Same meaning, different words or shape | 0 | 4 |
| Ambiguous: should ask back | 2 | 4 |
| Not answerable from the ledger | 8 | 9 |

**What failed.** 5 wrong answers given with no warning, and 2 questions wrongly declined.
- "How much did we sell" and "what did Orchard Foods bring in" were declined, because "sell" and "bring in" are not in the word list.
- "Revenue for the first half of 2026" was answered as the whole year to date: the translator does not know "first half" and fell back to the full year.
- "Revenue in 2025 excluding Delta Services" returned Delta Services' revenue alone. The translator saw the name and filtered to it. It does not read "excluding".
- "Revenue in Q2" and "Revenue in March" were answered for 2026. A missing year defaults to the latest year, where a careful analyst would ask which year.
- "Operating profit margin" was answered as operating profit. The translator matched the metric and ignored "margin".

The wrong answers matter more than the wrong refusals. A declined question costs a minute. A confident wrong figure can reach a report.

To rerun it: <code>node pipelines/ask-the-ledger/evaluate.mjs</code>. A test checks that the saved results match a fresh run.

**The live box and its checks.** Every question passes six checks in order: origin (only felipealveslab.com), per-visitor cap, daily cap, model call, SQL validation, then the answer. The validator accepts exactly one statement that starts with SELECT or WITH, rejects write and admin keywords, comments and quoted names, allows only the `ledger` table, and adds `LIMIT 100` when none is present. Since 2 November 2026 it also requires every LIMIT to be a whole number, lowered to 100 when larger (an external review found that `LIMIT -1` passed and returned all 1,008 rows), rejects recursive queries, set operations and functions that allocate large blobs, and never lets the ledger be joined, even with itself, so one question cannot turn 1,008 rows into a billion-row scan. 68 tests cover the validator, the caps, the origin check and the scorer; they pass. Requests that reach the model count against the caps even if they fail. The caps are approximate under bursts, because the counters are eventually consistent.

The recorded session uses two queries written by hand, not by a model; their rows were computed by running them on the ledger.

### Model benchmark

On 3 November 2026 two Workers AI models were asked to write SQL for the test questions, and the SQL was scored. This does not call the live Worker. It calls the same models through Cloudflare's REST API, with the Worker's own prompt (**baseline**) and the Worker's validator. By default the live Worker uses Qwen2.5-Coder 32B. A second prompt (**candidate**) adds the fixed reporting month, the gross-margin formula, the product's decline rules and the answer shape; its text is in `pipelines/ledger-eval/candidate-prompt.txt`.

Each query goes through the validator and then runs on four synthetic ledgers: the original, a second seed, one with zero revenue and one with perturbed amounts. A question counts as right only if it is right on all four, so a query that returns a constant or a hard-coded total fails. Figures must match exactly and have the expected shape. There are two question sets: the 47 on this page, and 20 newer ones.

| Questions, prompt, model | Right on all four ledgers | Figures right | Declined correctly | Declined wrongly | Neurons used |
| --- | --- | --- | --- | --- | --- |
| 47 page questions · baseline · Qwen2.5-Coder 32B | 31 of 47 | 26 of 34 | 6 of 13 | 1 | 1,104 |
| 47 page questions · candidate · Qwen2.5-Coder 32B | 35 of 47 | 27 of 34 | 9 of 13 | 3 | 2,255 |
| 47 page questions · candidate · Llama 3.2 3B | 1 of 47 | 1 of 34 | 0 of 13 | 0 | 321 |
| 20 newer questions · baseline · Qwen2.5-Coder 32B | 10 of 20 | 4 of 10 | 6 of 10 | 1 | 451 |
| 20 newer questions · candidate · Qwen2.5-Coder 32B | 13 of 20 | 7 of 10 | 8 of 10 | 2 | 932 |
| 20 newer questions · candidate · Llama 3.2 3B | 0 of 20 | 0 of 10 | 0 of 10 | 0 | 134 |

"Figures right" counts questions with an answer. "Declined correctly" counts questions the system should refuse. "Declined wrongly" counts questions with an answer that got no SQL. The last three columns are for the original ledger. Neurons are worked out from token counts at Cloudflare's list rates, not from its meter. The six runs used 5,197 neurons, about US$0.06 at list price, on the Workers Free plan.

**What this shows, limits first.**
- Each row is one run at temperature 0. How much the answers change from run to run is not measured. One question is worth 2 points of 47 and 5 points of 20.
- Neither question set tests the candidate prompt on questions it has not seen. The 47 were written with the translator. The 20 were written together with the candidate prompt, which names the cases to decline. So the candidate's gain (4 more questions right of 47, 3 more of 20) is plausible, not shown to carry over.
- The 40 of 47 for the keyword translator above is not comparable with these rows. It was scored by the page's older, looser check, which accepted a matching number in any column.
- Free-plan models only. No Claude model was run.

**What failed.**
- *Declining is the weak spot.* With the live prompt, Qwen declined correctly in 6 of 13 and 6 of 10 cases. The candidate prompt tells it to decline an ambiguous "profit", "costs" or "margin" and a month or quarter with no year. It still answered "What was the profit in 2025?" (L35), "What were our costs in 2026?" (L36), "Revenue in Q2" (L37), "Revenue in March" (L38), "Revenue in April." (V11) and "What was margin for 2025?" (V12), which is 6 of the 23 decline cases. Where the year was missing, the baseline assumed 2025 and the candidate assumed 2026.
- *The candidate prompt declined more answerable questions:* 3 of 47 and 2 of 20, against 1 and 1 for the baseline.
- *A filter nobody asked for.* For "Revenue in Q1 2026" (L03) the candidate's query added `entity = 'North Hub'` and returned 11,169. The right answer is 51,147.
- *The wrong period.* For "Operating expenses this year" (L20) both prompts summed January 2025 to September 2026 (125,394). The year to date is 58,488.
- *Divide by zero.* For "Gross margin for Delta Services for 2025" (V07) the candidate returned NULL on the zero-revenue ledger. Its prompt says the answer is zero when revenue is zero.
- *Ties.* "Which entity had the highest revenue in 2025?" (L13) and "Top two companies by sales in September 2026" (V08) fail on the zero-revenue ledger, where every company has zero revenue and the order is arbitrary. The candidate prompt says to rank ties by label, so for V08 and for L13 under that prompt this is a miss. The baseline prompt says nothing about ties, so for L13 under the baseline it is a weakness of the test.
- *Llama 3.2 3B was not usable here:* 1 of 47 and 0 of 20. Of the 47 queries it wrote, the validator rejected 6, 7 failed to run or timed out and 1 reply was a model error; the rest ran and gave wrong answers. It replied in about 0.6 seconds. Cloudflare's retirement date for this model is 20 November 2026 ([changelog](https://developers.cloudflare.com/changelog/post/2026-11-05-planned-model-deprecations/), opened 2026-11-14), so these two runs stay as a record and cannot be repeated.

To run a benchmark: GitHub Actions, workflow `ledger-benchmark`, which needs two repository secrets. To score the stored runs again: `node pipelines/ledger-eval/build-results.mjs --check`. The run files, their GitHub run numbers and the computed results are in [`data/ledger-eval/`](https://github.com/felipealves7/felipealveslab/tree/main/data/ledger-eval).

## Known limits and running cost

- **The data is synthetic.** Nothing here says how a real ledger behaves: real ledgers have adjustments, currencies, restatements and messy account names.
- **One author wrote both the questions and the translator.** The perfect score on plain questions mostly reflects that I wrote them in words the translator knows. It is not a benchmark and it does not show the translator is good.
- **47 questions is small.** One question moves the score by about two points.
- **Two models and two prompts have been scored, once each.** See the benchmark above. Every decline case in both question sets matches a rule written into the candidate prompt, and the 20 newer questions were written together with that prompt.
- **There is no paid-model comparison.** The free models' scores are in the benchmark above. How Claude Haiku would score has not been measured, and Haiku is not switched on.
- **The validator is a rule check, not a proof.** The database holds only synthetic data, so a bypass would expose nothing real. It cannot stop every slow query: a crafted one can still read the ledger many times over, for example through correlated subqueries. Cloudflare's free D1 allowance is 5 million rows read a day, and all queries stop once it is used until the reset at 00:00 UTC ([D1 pricing](https://developers.cloudflare.com/d1/platform/pricing/), opened 2026-11-02). So the worst case is a live box that stops answering for the rest of that day, with the recorded session still on the page.
- **Cost:** US$0 to start. Cloudflare's [pricing page](https://developers.cloudflare.com/workers-ai/platform/pricing/), opened on 2026-10-29, gives the free Workers AI allowance as 10,000 neurons a day on the free plan and says calls fail once it is used up, so nothing is billed. The benchmark measured about 23 neurons a question for the live Worker's model and prompt (1,104 neurons over 47 questions, at list rates), so the cap of 50 questions a day would use about 1,200 of the 10,000 free neurons. That is arithmetic on token counts, not Cloudflare's meter, and live questions may be longer. Benchmark runs share the same daily allowance. If Haiku is switched on later, the hard stop is a prepaid US$5 credit with auto-reload off. The rest of the page reads saved files and costs nothing.
